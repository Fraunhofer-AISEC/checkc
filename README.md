# checkc

checkc enables retrieval, evaluation and assessment of the configuration of containers running on a Linux kernel.
It operates at the kernel user-space API-level in an engine-agnostic manner
and is thereby applicable to containers launched by widely-used container engines.
The reports generated by checkc make the isolation characteristics transparent and understandable to human users.
This enables, for instance, configuration assessment before large-scale deployment on production systems
to ensure the target container configurations actually provide the intended level of isolation.

A detailed description of the underlying approach for container configuration assessment
can be found in the publication [Engine-Agnostic Evaluation of Container Isolation Characteristics](https://doi.org/10.1109/Trustcom66490.2025.00343).



# Usage Example

The following instructions outline an exemplary analysis run with checkc on a container launched by the container engine [podman](https://podman.io/).
They have been tested on a Debian Trixie image, provided by the [Debian Cloud Team](https://cdimage.debian.org/cdimage/cloud/) (debian-13-nocloud-amd64.tar.xz).

As checkc parses the entire file system, we recommend a clean, Linux-based host platform
for configuration assessment to speed up testing cycles.
Alternatively, this README also outlines the steps necessary
to prepare a clean Debian image for compiling checkc and following the instructions detailed in the following.

Although this README describes a Debian-based workflow,
checkc itself does not depend on a particular Linux distribution.

## Clone repository on host
```bash
git clone https://github.com/Fraunhofer-AISEC/checkc
```

## (optional) Prepare VM
As the host-side data collection run of checkc needs to be executed
with root privileges (sudo), we recommend leveraging a VM.
Therefore, the following instructions outline
a possible way to set up a clean VM to run the checkc usage example.

> [!CAUTION]
> qemu-img silently truncates/enlarges existing files.
> Make sure the specified target paths are correct and the target files do not exist
> before executing any of the following commands!

- Install QEMU and tooling for image creation/resizing
  ```bash
  sudo apt install qemu-system-x86 qemu-utils libguestfs-tools
  ```

- Download image debian-13-nocloud-amd64.tar.xz at https://cloud.debian.org/images/cloud/trixie/latest/
  and unpack it, obtaining the image `disk.raw`

- Enlarge the image to around 10GB to ensure there is enough space to build checkc.
  The following instructions assume the Debian image to be called `disk.raw`.
  The enlarged file is called `disk-10g.raw`.
  Please ensure the target file does not yet exist on your system.

  ```bash
  export LIBGUESTFS_BACKEND=direct

  # check libguestfs-tools working
  libguestfs-test-tool 

  # discover the partition holding the operating system, e.g. /dev/sda1
  ROOT=$(guestfish --ro -a disk.raw run : inspect-os)
  echo "root partition: $ROOT"

  # (optional) Manually check partition layout of disk.raw
  virt-filesystems --format=raw  --long --parts --filesystems -h -a disk.raw

  qemu-img create -f raw disk-10g.raw 10G
  virt-resize --expand "$ROOT" disk.raw disk-10g.raw
  ```

- Run the resized image.
  On first boot, you are asked to supply a root password.
  ```bash
  cd checkc/scripts/vm/
  bash run_image.sh /path/to/disk-10g.raw
  ```

- Create regular user to execute the checkc usage example and add it to group sudo
  ```bash
  adduser user
  gpasswd -a user sudo
  ```
- Restart the VM and log in as the newly created user

## Prepare checkc
We recommend running the following steps inside a virtual machine.


### Install dependencies

- Debian Packages
  ```bash
  sudo apt update
  sudo apt install git build-essential protobuf-compiler podman curl
  ```

- Rust (standard installation) as described at https://rust-lang.org/tools/install/

- Restart to ensure the test containers can be started properly

### Clone repository inside VM
```bash
git clone https://github.com/Fraunhofer-AISEC/checkc
```

### Build

```bash
cd checkc
cargo build --target x86_64-unknown-linux-gnu --release
```

## Run example
### Enter directory scripts/podman
```bash
cd scripts/podman
```

### Start example and reference containers
```bash
bash run_containers.sh
```

### Run checkc

> [!CAUTION]
> The following script executes the previously built binary executable with root privileges (sudo).
> We therefore strongly recommend the use of a virtual machine as outlined above.

> [!NOTE]
> Script needs to be run as the same user that also started the podman containers

```bash
bash run_example_podman.sh
```
